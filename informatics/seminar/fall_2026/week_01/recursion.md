# Рекурсия

Един обект се нарича **рекурсивен**, ако се съдържа в себе си или е дефиниран чрез себе си.

В компютърната информатика рекурсията е сред най-мощните инженерни подходи. Тя позволява както елегантното дефиниране на сложни **алгоритми**, така и изграждането на гъвкави **структури от данни**.

Въпреки своите предимства, в практиката нерегулираното или неправилното използване на рекурсивни извиквания често води до висока **времева и пространствена сложност**.

## 1. Класификация и механизъм

Основно средство за реализиране на рекурсивни процеси в програмните езици са **функциите**. В зависимост от топологията на извикванията, рекурсията се разделя на:

- **Пряка (директна):** Сценарий, при който в тялото на дадена функция $f$ се съдържа изрично (директно) обръщение към същата функция $f$.
- **Непряка (косвена):** Комплексен сценарий на взаимно застъпване, при който функция $f_1$ извършва обръщение към функция $f_2$, функция $f_2$ към $f_3$, ..., а функция $f_n$ затваря цикъла с обръщение обратно към $f_1$.

## 2. Предимства, недостатъци и инженерни компромиси

Архитектурната специфика на рекурсията се състои в замяната на итеративния контрол (цикли) с автоматично управление на състоянието чрез **системния стек**.

### 2.1. Основни предимства

- **Ясна и кратка реализация:** Рекурсивното решение често следва директно логиката на самия проблем. Това е особено удобно при задачи, които естествено се описват чрез рекурентни зависимости или индуктивни определения.
- **Естествено обработване на йерархични структури:** Рекурсията е подходяща за работа с дървета, графи (DFS обхождане), вложени структури (JSON) и файлови системи. Всеки елемент или подструктура може да бъде обработен по един и същ начин.
- **Автоматично съхраняване на състоянието:** При алгоритми от типа "Разделяй и владей" всяко рекурсивно извикване запазва необходимото състояние в системния стек. При връщане от извикването това състояние се възстановява автоматично.
- **Използване на системния стек:** Когато задачата изисква обработка в обратен ред (LIFO), рекурсията може да използва системния стек вместо изрично да се създава допълнителна стекова структура.

### 2.2. Основни недостатъци

- **По-голяма консумация на памет:** Всяко рекурсивно извикване създава нова стекова рамка, в която се съхраняват аргументи, локални променливи и адрес за връщане. При дълбока рекурсия използваната памет може да нарасне до $\mathcal{O}(h)$, където $h$ е максималната дълбочина на рекурсията.
- **Риск от препълване на стека:** Системният стек има ограничен размер. При прекалено дълбока рекурсия наличната памет може да се изчерпи и програмата да прекрати изпълнението си с грешка (*stack overflow*).
- **Времеви овърхед при извикване на функции:** На ниско ниво всяко обръщение изисква запис в стека, превключване на контекста на процесора и инструкции `CALL`/`RET`, което прави рекурсията по-бавна от стандартен `for` или `while` цикъл.
- **Повторни изчисления:** При някои рекурсивни алгоритми едни и същи подзадачи се решават многократно. Например наивното рекурсивно изчисляване на числата на Фибоначи води до експоненциална времева сложност $\mathcal{O}(2^n)$. Мемоизацията може да избегне тези повторни изчисления.
- **По-трудно дебъгване:** При дълбока рекурсия стекът от извиквания може да стане много голям и да затрудни проследяването на изпълнението и откриването на грешки.

### 2.3. Инженерни компромиси в практиката

- **Оптимизация на опашната рекурсия:** Ако рекурсивното извикване е последната операция във функцията, съвременните компилатори (GCC/Clang с `-O2`/`-O3`) я преобразуват вътрешно в итеративен скок (`jmp`), редуцирайки използваната памет до $\mathcal{O}(1)$.
- **Трансформация с изричен стек:** Когато рискът от *stack overflow* е критичен, алгоритъмът се преписва итеративно, а системният стек се заменя с динамична структура (`std::stack`) в *heap* паметта.

## 3. Критерии за коректност

За да бъде един рекурсивен алгоритъм дефиниран правилно и да гарантира **краен резултат**, е необходимо строго съблюдаване на следните три фундаментални условия:

- **Разбиване на подзадачи:** Задачата, която разглеждаме, трябва да се разбива на подзадачи, за които (рекурсивно) може да се приложи същият алгоритъм. Комбинирането на решенията на всички подзадачи трябва да води до решение на изходната задача.
- **Дъно на рекурсията:** Алгоритъмът трябва да гарантира, че след краен брой стъпки ще се достигне до частен случай (дъно на рекурсията), чието решение е известно или може да бъде намерено директно, без последващи рекурсивни извиквания.
- **Сходимост:** Всяко междинно рекурсивно извикване трябва математически да модифицира входните параметри така, че състоянието на задачата монотонно да се стреми към някой от дефинираните базови случаи (аналогично на изискването за наличие на база при математическата индукция).

## 4. Примери

### 4.1. Факториел и опашкова рекурсия

Първият пример демонстрира изчисляването на факториел и илюстрира концепцията за **опашкова рекурсия**.

```cpp
// Класическа версия, която натоварва системния стек
long long factorial(int n) {
    if (n == 0) return 1;
    
    // Умножението се извършва след рекурсивното извикване;
    // процесорът е длъжен да запази текущата стекова рамка жива,
    // за да съхрани стойността на n до приключването на вложената функция;
    // при n = 100000 това ще доведе до препълване на стека
    return factorial(n - 1) * n;
}
```

Оптимизирана версия с **акумулатор**:

```cpp
// Помощна функция
long long factorial_helper(int n, long long accumulator) {
    // Базовият случай връща натрупания тотал
    if (n == 0) return accumulator;
    
    // Математическата операция се случва преди рекурсивното извикване
    return factorial_helper(n - 1, accumulator * n);
}

// Изчистена обвиваща функция за крайния потребител
long long factorial(int n) {
    return factorial_helper(n, 1);
}
```

Какво генерира компилаторът зад кулисите при оптимизация (*tail call optimization*):

```cpp
long long factorial_tco_compiled(int n) {
    long long accumulator = 1;
    
    while (true) {
        if (n == 0) return accumulator;
        
        accumulator *= n;
        
        // Рекурсивната стъпка се превръща в декрементиране на цикъл
        --n;
    }
}
```

### 4.2. Ханойски кули

Дадени са $n$ на брой диска с различни диаметри, както и три стълба $A$, $B$ и $C$. Дисковете са нанизани върху първия стълб по реда на намаляване на размера им и образуват кула. Целта е да се прехвърлят от първия стълб върху последния при спазване на следните правила:

- При всеки ход може да бъде преместен **един диск** и този диск трябва да бъде най-горен за някой от стълбовете.
- Диск с **по-голям диаметър не може** да бъде поставен върху такъв с по-малък.

Това е класическият алгоритъм за решаване на задачата:

```cpp
#include <iostream>

// Помощна функция за визуализиране на единично преместване на диск
void print_move(int begin, int end, int n) {
    std::cout << "Move disk #" << n << " from peg #" << begin << " to peg #" << end << ".\n";
}

// Рекурсивна функция, имплементираща дървовидна логика
void solve_tower_of_hanoi(int begin, int end, int n) {
    if (n <= 0) return;
    
    // Изчисляване на помощния стълб
    int auxiliary = 6 - (begin + end);
    
    // Местим всичко над текущия диск върху помощния стълб, за да го освободим
    solve_tower_of_hanoi(begin, auxiliary, n - 1);
    
    // Пренасяме самия диск на крайната му позиция
    print_move(begin, end, n);
    
    // Прехвърляме останалата част от кулата върху вече преместения диск
    solve_tower_of_hanoi(auxiliary, end, n - 1);
}
```

Алгоритъмът за Ханойските кули перфектно показва връзката между програмирането и **математическата индукция**. Когато пишем рекурсивното решение, няма нужда да проследяваме наум всички милиони стъпки. Вместо това просто разбиваме проблема на три прости части:

- **Базов случай:** Ако имаме само един диск, решението е тривиално. Просто го преместваме от началния на крайния стълб. В кода това е нашето дъно на рекурсията.
- **Индуктивно предположение:** Приемаме за дадено, че нашият алгоритъм вече знае как перфектно да премести кула от $n - 1$ диска от един стълб на друг.
- **Индуктивна стъпка:** За да решим проблема за $n$ диска, прилагаме индуктивното предположение в три стъпки. Първо преместваме горните $n - 1$ диска върху помощния стълб, за да освободим най-големия, след което прехвърляме въпросния $n$-ти диск директно върху целта, и накрая връщаме обратно предходните $n - 1$ диска върху него. По този начин сложният преход за $n$ елемента се свежда изцяло до вече доказаното (или имплементирано) правило за $n - 1$ елемента.

#### Сложност на алгоритъма

- **Времева сложност:** $\mathcal{O}(2^n)$, където $n$ е броят на дисковете. Това се дължи на факта, че при всяко рекурсивно извикване задачата се разделя на два по-малки подпроблема, което води до експоненциален растеж.
- **Пространствена сложност:** $\mathcal{O}(n)$ заради системния стек от рекурсивни извиквания, тъй като всяко от тях добавя нова рамка към него.

### 4.3. Пермутации без повторение

Разглеждаме $n$-елементното множество $A = \{ a_1, a_2, \dots, a_n \}$. Всяка наредена $n$-торка, получена с елементите от $A$, като всеки елемент от $A$ участва точно веднъж, се нарича **пермутация**.

За компютърното генериране на пермутации ще използваме рекурсивен алгоритъм:

```cpp
#include <iostream>

const unsigned int MAX_ELEMENTS = 100;
const unsigned int PERMUTATION_SIZE = 3;

// Ако is_used[i] е true, това означава, че числото i
// вече е в текущата ни последователност, така че
// не можем да го използваме повторно
bool is_used[MAX_ELEMENTS];

// Съхранява последователността от числа, която се изгражда в момента
unsigned int current_permutation[MAX_ELEMENTS];

void print() {
    unsigned int i;
    
    for (i = 0; i < PERMUTATION_SIZE; ++i) {
        std::cout << current_permutation[i] + 1 << " ";
    }
    
    std::cout << "\n";
}

// Функцията изгражда пермутацията елемент по елемент,
// като на всяка стъпка се опитва да попълни текущата позиция
void permute(unsigned int current_position) {
    unsigned int i;
    
    // Намерили сме пълна пермутация
    if (PERMUTATION_SIZE <= current_position) {
        print();
        
        return;
    }
    
    // Въртим през всички възможни числа
    for (i = 0; i < PERMUTATION_SIZE; ++i) {
        // Числото все още е свободно
        if (!is_used[i]) {
            // Маркираме го като заето
            is_used[i] = true;
            
            // Добавяме го в текущата позиция
            current_permutation[current_position] = i;
            
            // Извикваме същата функция, за да попълни
            // следващата свободна позиция вдясно
            permute(current_position + 1);
            
            // След като сме генерирали всички пермутации,
            // започващи с числото i на тази позиция, го маркираме като свободно,
            // за да може да се падне на по-десни (следващи) позиции в другите комбинации
            is_used[i] = false;
        }
    }
}

int main() {
    unsigned int i;
    
    for (i = 0; i < PERMUTATION_SIZE; ++i) {
        is_used[i] = false;
    }
    
    permute(0);
    
    return 0;
}
```

Докато при 4.1. рекурсията се движеше по права линия, а при 4.2. се разклоняваше на две, тук се сблъскваме с нов тип структура: **рекурсивен *backtracking* (връщане назад)**.

Вместо просто да изчислим стойност или да преместим обект, ние използваме рекурсията, за да изследваме всички потенциални пътища в едно огромно **пространство от решения**. Сега алгоритъмът не търси единичен изход, а систематично "разлиства" всяко възможно разклонение.
