# Шаблони

## 1. Същност и инстанциране

Шаблонът представлява езикова конструкция, която служи като "чертеж" за компилатора за създаване на функции или класове с обща логика. Вместо да повтаряме един и същ код за различни типове данни, дефинираме шаблон, използвайки ключовата дума `typename` или `class` и произволен типов параметър (по традиция `T`).

Ето класически пример за шаблон на функция, която връща по-малката от две стойности:

```cpp
template <typename T>
T minimum(const T& lhs, const T& rhs) {
    return lhs < rhs ? lhs : rhs;
}
```

Тук `T` играе ролята на пълнител (*placeholder*), който определя както типа на връщаната стойност, така и типовете на двата входящи параметъра `lhs` и `rhs`. За да се компилира кодът успешно, съответният тип трябва да поддържа операциите в тялото на функцията - в този случай оператора за сравнение `<`.

Процесът, при който компилаторът замества шаблонния параметър с реален тип (напр. `int` или `double`) и генерира специализиран машинен код за всяка уникална комбинация, се нарича *template instantiation*. Това може да стане по два начина при извикване на функцията.

Първият подход е чрез експлицитно указване на типа в ъглови скоби:

```cpp
int a = get_a();
int b = get_b();
int result = minimum<int>(a, b);
```

Вторият и по-често използван подход е автоматичното извеждане (*template argument deduction*), при което компилаторът сам отгатва типа на базата на подадените аргументи:

```cpp
int result = minimum(a, b);
```

Независимо дали типът се извежда автоматично или не, получената в крайна сметка функция е напълно еквивалентна на ръчно написаната реализация за съответния тип.

## 2. Видове шаблонни параметри

### 2.1. Типови параметри

Типовите параметри позволяват на шаблонната функция или клас да работят с произволни вградени или потребителски типове. Те се дефинират чрез ключовата дума `typename` (или `class`), като имената им се избират произволно.

Ако шаблонът изисква повече от един тип, те се изброяват в ъгловите скоби, разделени със запетая:

```cpp
template <typename T, typename U, typename V>
class Foo {
    // Вътрешна логика, използваща T, U и V
};
```

В контекста на шаблонните параметри ключовите думи `typename` и `class` са взаимозаменяеми. Следователно горният запис е напълно еквивалентен на:

```cpp
template <class T, class U, class V>
class Foo {
    // ...
};
```

#### Как работи това на практика?

Когато напишем шаблон, той може да работи с всичко - от стандартни типове като `int` и `double`, до наши собствени класове. Единственото изискване към даден тип е да поддържа операциите, които шаблонът извършва в тялото си.

Например, ако използваме вече познатата ни функция `minimum`:

```cpp
template <typename T>
T minimum(const T& lhs, const T& rhs) {
    return lhs < rhs ? lhs : rhs;
}
```

Тя ще работи перфектно с числа, защото те поддържат оператора за сравнение `<`. Но ако подадем наш собствен клас, който няма такъв оператор, компилаторът ще ни върне грешка, защото изискването на шаблона не е покритo.

### 2.2. Нетипови параметри

Освен типове, шаблоните в C++ могат да приемат и конкретни константни стойности като параметри, които задължително се изчисляват по време на компилация.

Този подход е изключително удобен, когато искаме да създадем структура с фиксиран размер, който да се определя при самото инстанциране (точно както работи стандартният `std::array`):

```cpp
template <typename T, std::size_t Capacity>
class MyArray {
    T data[Capacity];

public:
    // ...
};
```

Когато използваме шаблона, подаваме както типа на елементите, така и стойността на нетиповия параметър в ъгловите скоби:

```cpp
int main() {
    // Създаваме масив с точно 5 цели числа
    MyArray<int, 5> numbers;
    
    // Създаваме масив с точно 100 десетични числа
    MyArray<double, 100> measurements;
    
    return 0;
}
```

Тъй като `Capacity` е константа, известна предварително, компилаторът знае точния размер на масива и може да задели паметта за него директно, което носи следните фундаментални предимства:

- **Нулева памет за самия размер:** Ако размерът се задаваше през конструктора, класът щеше да е принуден да пази стойността му като член-данна. При нетиповия параметър стойността е вградена - тя не заема нито един байт памет в обекта.
- **Строга типова безопасност:** В C++ `MyArray<int, 5>` и `MyArray<int, 10>` са напълно различни типове данни. Ако имаме функция, която приема масив с точно 5 елемента, компилаторът няма да ни позволи случайно да му подадем масив с 10 елемента. Грешката се хваща още по време на компилация.

### 2.3. Шаблони като параметри на шаблони

Шаблоните в C++ могат да приемат друг шаблон като свой параметър. Това позволява изграждането на гъвкави архитектури, при които външният клас или функция работи с по-обща шаблонна структура (напр. политика на поведение, стратегия, фабрика или друг помощен компонент), без да се обвързва предварително с конкретен тип.

Ето пример, при който един клас приема шаблон за стратегия или контейнер:

```cpp
template <typename T, std::size_t Capacity, template <typename, std::size_t> class Policy>
class SmartManager {
    Policy<T, Capacity> activePolicy;

public:
    // Методи, използващи подадената шаблонна структура
};
```

Когато потребителят инстанцира `SmartManager`, той подава конкретната структура като аргумент:

```cpp
int main() {
    // Създаваме мениджър, който използва MyArray като политика/структура
    SmartManager<int, 20, MyArray> manager;
    
    return 0;
}
```

По този начин `SmartManager` остава напълно независим от конкретната имплементация - той само изисква подаденият шаблон да отговаря на очакваната структурна форма (`template <typename, std::size_t>`).

#### Важна особеност при именуването

Имената на вътрешните параметри в дефиницията на параметъра-шаблон служат единствено за синтактична коректност и не могат да се използват като независими типове в тялото на основния клас:

```cpp
template <typename T, template <typename U, std::size_t> class Container>
class SmartWrapper {
    // Грешка: U съществува само в декларацията на параметъра-шаблон
    U u;
};
```

Имената на тези вътрешни параметри дори не са задължителни и често се изпускат (както е показано в първия пример с `template <typename, std::size_t>`), за да се подчертае, че те са само структурни пълнители.

### 2.4. Аргументи по подразбиране

Шаблонните параметри могат да имат стойности по подразбиране, което опростява използването им в стандартни сценарии.

Например, можем да дефинираме клас, чийто тип на данните или чийто размер по подразбиране е предварително зададен:

```cpp
template <typename T = int, std::size_t Capacity = 100>
class MyFixedArray {
    T data[Capacity];

public:
    // ...
};
```

Когато извикваме шаблона, можем да пропуснем параметрите, чиито стандартни стойности ни устройват:

```cpp
int main() {
    // Използва int и размер 100 по подразбиране
    MyFixedArray<> standardArray;
    
    // Използва double, но запазва размер 100
    MyFixedArray<double> doubleArray;
    
    // Задава изцяло собствени стойности
    MyFixedArray<char, 50> customArray;
    
    return 0;
}
```

## 3. Разделна компилация

При обикновените класове декларациите обикновено се записват в хедър файл (`.h` или `.hpp`), а дефинициите на методите - в отделен `.cpp` файл. При шаблоните това разделяне изисква допълнително внимание, тъй като компилаторът трябва да разполага с дефиницията на шаблона, когато създава конкретна инстанция.

### 3.1. Причина за проблема

При инстанцирането на шаблон компилаторът използва неговата дефиниция, за да генерира код за конкретния тип. Ако дефиницията е скрита в отделен `.cpp` файл, тя може да не е достъпна в момента, когато се използва шаблонът. В резултат компилацията на отделните файлове може да премине успешно, но при свързването (*linking*) да възникне грешка, тъй като липсва необходимата специализация на функцията или метода за съответния тип.

Да разгледаме следния пример:

```cpp
// minimum.hpp
template <typename T>
T minimum(const T& lhs, const T& rhs);
```

```cpp
// minimum.cpp
#include "minimum.hpp"

template <typename T>
T minimum(const T& lhs, const T& rhs) {
    return lhs < rhs ? lhs : rhs;
}
```

```cpp
// main.cpp
#include "minimum.hpp"

int main() {
    int result = minimum(3, 7);
    
    return 0;
}
```

В `main.cpp` е видима само декларацията на `minimum`, но не и нейното тяло. Следователно компилаторът не разполага с необходимата дефиниция, за да инстанцира шаблона за типа `int`. Отделното компилиране на `minimum.cpp` не гарантира, че ще бъде генериран код за този тип, поради което програмата може да завърши с грешка при свързването.

### 3.2. Начини за организация на шаблонния код

В практиката се използват два основни подхода, а когато наборът от поддържани типове е предварително известен, е възможно и експлицитно инстанциране.

#### 3.2.1. Дефиниция в хедър файла

Това е най-разпространеният подход. Декларацията и дефиницията на шаблона се разполагат в един и същ хедър файл, така че да са достъпни на местата, където шаблонът се използва.

```cpp
// minimum.hpp
template <typename T>
T minimum(const T& lhs, const T& rhs) {
    return lhs < rhs ? lhs : rhs;
}
```

```cpp
// main.cpp
#include "minimum.hpp"

int main() {
    int smaller = minimum(3, 7);
    
    double value = minimum(2.5, 1.8);
    
    return 0;
}
```

При компилацията на `main.cpp` дефиницията е достъпна и компилаторът може да инстанцира функцията както за `int`, така и за `double`, при условие че съответните типове поддържат необходимите операции.

#### 3.2.2. Дефиниция в отделен файл с включване в хедъра

Когато искаме да отделим декларацията от имплементацията за по-добра организация на кода, можем да използваме допълнителен файл, напр. `.inl`. Той съдържа дефинициите на шаблонните методи и се включва в края на хедъра.

```cpp
// box.hpp
#pragma once

template <typename T>
class Box {
    T value;

public:
    Box(const T& value);
    T getValue() const;
};

#include "box.inl"
```

```cpp
// box.inl
template <typename T>
Box<T>::Box(const T& value) : value(value) {}

template <typename T>
T Box<T>::getValue() const {
    return value;
}
```

```cpp
// main.cpp
#include "box.hpp"

int main() {
    Box<double> decimalBox(3.14);
    double decimal = decimalBox.getValue();
    
    Box<int> integerBox(42);
    int number = integerBox.getValue();
    
    return 0;
}
```

Макар дефинициите да са физически отделени в друг файл, включването на `box.inl` прави съдържанието му достъпно за компилатора при използването на шаблона. По този начин се запазва разделението на кода, без да се губи възможността за инстанциране на различни типове.

#### 3.2.3. Експлицитно инстанциране

Когато предварително знаем за кои типове ще използваме шаблона, можем да запазим дефиницията в `.cpp` файл и изрично да укажем за кои типове трябва да бъде генериран код.

```cpp
// box.hpp
#pragma once

template <typename T>
class Box {
    T value;

public:
    Box(const T& value);
    T getValue() const;
};
```

```cpp
// box.cpp
#include "box.hpp"

template <typename T>
Box<T>::Box(const T& value) : value(value) {}

template <typename T>
T Box<T>::getValue() const {
    return value;
}

// Експлицитно инстанциране
template class Box<double>;
template class Box<int>;
```

Записите `template class Box<int>;` и `template class Box<double>;` указват на компилатора да инстанцира класа за двата посочени типа. Така необходимият код се генерира в `box.cpp`, въпреки че дефинициите не са включени в хедъра.

Този подход е подходящ, когато поддържаните типове са ограничени и предварително известни. Ако се използва друг тип, напр. `Box<char>`, трябва да се осигури съответната инстанция. Самото наличие на декларацията в хедъра не е достатъчно за генериране на липсващата дефиниция.
